# PEXA (Property Exchange Australia)

> PEXA operates Australia's dominant Electronic Lodgement Network — the digital rail on which
> property is settled and title dealings are lodged with the state land registries. It publishes a
> real, versioned, multi-product API estate (Exchange, Projects, Notification/webhooks, Standalone
> Discharge, PEXA Plus Marketplace) with machine-readable contracts, a named managed test
> environment, published per-transaction pricing and declared OAuth 2.0 scopes. Access is gated: the
> developer portal and all credentials require a signed PEXA API Agreement, and the ARNECC Model
> Operating Requirements oblige PEXA to offer that access to third parties on an equivalent basis.

## Access model

- Not self-serve. Register at https://www.pexa.com.au/pexa-apis/, PEXA validates and approves, test
  credentials are emailed, production requires a signed PEXA API Agreement.
- Auth: OAuth 2.0 client credentials (M2M) or authorization code (B2C, individual PEXA login + MFA),
  or mutual TLS. Tokens last 12 hours. TLS 1.2 minimum.
- Production token endpoint: https://auth.pexa.com.au/oauth/token
- Test token endpoint: https://auth-tst.pexalabs.com.au/oauth/token
- Credential requests: apisupport@pexa.com.au
- Pricing is per Settled Workspace, published at https://www.pexa.com.au/api-pricing/

## APIs

- [PEXA Exchange API](https://developer.pexa.com.au/Exchange/api/apireference/): workspaces,
  invitations, participants, land title references, documents, conversations, financial settlement
  line items, settlement dates, settlement completion records. Swagger 2.0, paths /v2-/v6.
- [PEXA Projects API](https://developer.pexa.com.au/Projects/api/apireference/): multi-lot
  development settlements — projects, lots, statuses, parties, participants, financials. OpenAPI
  3.0.3, /v4.
- [PEXA Notification Service API](https://developer.pexa.com.au/Webhooks/api/apireference/): webhook
  registration, event selection and shared-secret rotation; declares SubscriberNotification and
  NonSubscriberNotification webhooks. OpenAPI 3.1.0. Premium billed API.
- [PEXA Standalone Discharge Experience API](https://developer.pexa.com.au/EXP_ConsolidatedDischarge/api/apireference/):
  consolidated standalone mortgage discharge for financial institutions. OpenAPI 3.1.0, /v1.
- [PEXA Plus Marketplace B2B API](https://developer.pexa.com.au/Marketplace/api/apireference/):
  health, title search ordering and billing. OpenAPI 3.0.3, https://plus.pexa.com.au/api/plus/v1

## Notes for agents

- No PEXA operation is callable anonymously. Do not attempt to discover credentials.
- Exchange REST writes have NO idempotency key. Never blind-retry a POST or PUT; re-read state first.
- Inbound webhooks DO have one: dedupe on the `webhook-id` header, which is stable across retries.
- The Exchange contract serves /v2 through /v6 concurrently; take paths verbatim from the spec.
- Signing documents, authorising source line items and accepting settlement move real money against
  real land titles. Treat them as human-in-the-loop.
- No published rate limits and no X-RateLimit-* headers. Poll conservatively; prefer webhooks.
- RESO does not apply. It is a North American MLS standard with no bearing on Australian
  e-conveyancing; PEXA neither claims nor implies alignment with it.
